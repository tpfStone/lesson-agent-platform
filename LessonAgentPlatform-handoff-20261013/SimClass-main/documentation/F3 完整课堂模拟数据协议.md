# F3 完整课堂模拟数据协议

## 1. Session schema 2.0

```json
{
  "schemaVersion": "2.0",
  "sessionId": "uuid",
  "lessonId": "F2/F4 lesson id",
  "versionId": "lesson version id",
  "status": "RUNNING",
  "modelMode": "REAL",
  "modelProvider": "openai-compatible",
  "modelName": "model-id",
  "startedAt": "ISO-8601 UTC",
  "finishedAt": null,
  "stopReason": null,
  "pauseReason": null,
  "limits": {
    "maxEvents": 60,
    "maxWallClockSeconds": 900,
    "maxConsecutiveTimeouts": 3,
    "timeoutSeconds": 15.0
  },
  "materials": []
}
```

状态只允许：`READY/RUNNING/PAUSED/STOPPING/COMPLETED/INTERRUPTED/FAILED`。
worker 异常写 `FAILED`；上限和人工提前结束写 `INTERRUPTED`；不得把线程死亡伪装成
`PAUSED`。

## 2. Material

正式字段：

```json
{
  "materialId": "stable-id",
  "title": "章节标题",
  "teachingScript": "教学脚本",
  "keyPoints": [],
  "sourceSectionId": "F2/F4 section id",
  "metadata": {}
}
```

Adapter 同时接受现有 F3/F4 的 `id/teaching_script/key_points`，进入 Classroom 前归一化，
不会修改原 Agent 对 snake_case 的读取方式。

## 3. Event

每个 Manager -> Executor -> Agent 尝试形成独立稳定事件：

```json
{
  "eventId": "uuid",
  "sequence": 7,
  "sessionId": "uuid",
  "occurredAt": "ISO-8601 UTC",
  "completedAt": "ISO-8601 UTC",
  "wallClockDurationMs": 2840,
  "estimatedTeachingSeconds": null,
  "estimated": false,
  "trigger": {"type": "USER_INPUT", "content": "k 可以等于 0 吗"},
  "managerDecision": {
    "speaker": "teacher",
    "function": "answer_question",
    "reason": "需要回应概念疑问",
    "endClass": false
  },
  "speaker": "teacher",
  "roleLabel": "教师",
  "function": "answer_question",
  "content": "...",
  "material": {
    "materialId": "m-1",
    "title": "一次函数定义",
    "sourceSectionId": "sec-1"
  },
  "status": "COMPLETED",
  "error": null
}
```

`wallClockDurationMs` 只代表系统执行耗时。当前没有教学时长估算器，因此
`estimatedTeachingSeconds=null`，绝不把 API 延迟冒充教学分钟。

失败轮也保留事件，`status=FAILED` 并写 `error`，但不会杀死 session worker。

## 5. IssueAnalysis schema 1.0

F3 原生类别：

```text
student_misconception
insufficient_explanation
participation_imbalance
interaction_gap
pace_risk
material_transition
assessment_gap
other
```

严重度：`LOW/MEDIUM/HIGH/CRITICAL`。

每条 issue 至少一个 evidence：

```json
{
  "nativeIssueId": "ISSUE-01",
  "category": "interaction_gap",
  "severity": "MEDIUM",
  "title": "课堂提问缺少后续显式回应",
  "problem": "...",
  "evidence": [
    {
      "eventId": "uuid",
      "sequence": 5,
      "speaker": "inquisitive_mind",
      "contentQuote": "逐字来自 event.content"
    }
  ],
  "resolvedInSimulation": false,
  "resolutionEvidenceEventIds": [],
  "resolution": null,
  "suggestedAction": "...",
  "targetLessonSection": "一次函数定义",
  "confidence": 0.9
}
```

## 6. EvidenceValidator 确定性规则

1. eventId 必须存在；
2. sequence/speaker 必须与事件一致；
3. contentQuote 必须是 `event.content` 的真实子串；
4. resolution event 必须晚于问题证据；
5. resolved=true 时必须提供 resolutionEvidenceEventIds；
6. targetLessonSection 必须能映射到 materialId/title/sourceSectionId；
7. category/severity 必须在白名单；
8. 单个分析窗口最多接收 12 条候选 issue。

验证器不会“修补”假证据；第一次失败后只允许 LLM 再生成一次，第二次仍不合法的
issue 直接删除并记录 warning。

## 7. Issue 后处理与优先级治理

EvidenceValidator 通过后的候选问题进入确定性的 `IssueConsolidator`：

1. 把 materialId/title/sourceSectionId 统一映射为稳定 `materialId`；
2. 同一材料内的 `interaction_gap / assessment_gap / participation_imbalance` 视为同一
   “学生作答—反馈闭环”根因时合并，并保留真实 evidence 的并集；
3. `student_misconception / insufficient_explanation / material_transition / pace_risk` 等
   独立教学问题不因处于同一材料而被强行合并；
4. 按 severity、confidence、重复出现次数、evidence 数量排序；
5. 默认只保留 Top 5 最有价值 issues；
6. 合并结果再经过一次全局 EvidenceValidator；
7. `actionItems[]` 在 Top 5 确定后生成，因此不会出现“5 个问题却有 12 条重复建议”。

## 8. 与公共问题协议衔接

F3 只输出原生 `issues[]/actionItems[]`，不直接创建或修改教案版本。
统一平台负责将 F3 category 映射到 `CommonIssue.category`，并按 lessonId/versionId/sessionId
写入公共上下文层，供 F2/F4 按需读取。
