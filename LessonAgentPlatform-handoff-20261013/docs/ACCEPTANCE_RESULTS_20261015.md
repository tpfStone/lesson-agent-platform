### HTTP：增加真正运行的服务端验收

### F2：补足真实制品与输入边界

原先只有 2 项 DOCX 用例，新增 6 项：用真实导出器产生 manifest/JSON/DOCX，验证正确配对恢复且不调用模型；DOCX 篡改、JSON 篡改、缺失 manifest 不能冒充可信生成稿；非 ZIP 输入拒绝；大小恰好等于限制允许、超过 1 字节拒绝。

### F3：首次持久化失败后的幂等恢复

新增 `auto_start=False/True` 两项故障注入。原逻辑先发布内存索引再落盘，第一次写文件失败后重试会错误返回 reused，既没落盘也可能没启动。现在先成功落盘，再发布索引。验证重试落盘、需要时只启动一次、再次重试不重复、服务重建后仍复用同一会话。

### F4：畸形结构和纯文本来源冲突

新增 4 项 API 边界回归：null block、错误类型 teachingProcess、错误类型 columnBindings 原先返回 500，现返回 422 且不创建残留会话；无 structured_content 时同 request_key 更换 source_binding 原先被当成重复成功，现返回 409。原会话来源保持不变，同来源重试仍成功。通过对持久化来源单独比较，兼容历史纯文本 input_hash。

后者是 F4 公共 API 接受的组合；当前 Java 正常结构桥接路径通常同时提交结构和来源，不将它描述成所有平台请求都会触发的问题。

### 前端与运维

单测由 5 增至 15：历史缺失与损坏错误分流、文档/blocks 类型异常、null block、合法空 blocks、来源版本不匹配、组件卸载后晚到响应、退出后私有任务/结果/附件响应、旧 logout 失败不能破坏新登录。

修复 `useVersionDocument` 对损坏 blocks 仍标记 ready 的问题，明确展示错误。清理 23 项 ESLint 错误：补浏览器 globals、移除未用代码、改写 finally 清理；用竞态回归保留旧请求被忽略的语义。

实际 Linux 测试发现当前工作区 `health-check.sh` 含 CRLF，Bash 报 `do\r` 语法错误；已按已有 `.gitattributes` 归一为 LF。Git 内规范化内容可能不显示此字节变化，交接时以实际运行和新摘要清单为准。

## 4. 必须补做的人工/真实环境验收

以下步骤包含操作、预期和留证要求。建议使用专门验收环境及脱敏材料，按 A→J 顺序进行；每项记录时间、账号、lessonId/versionId/jobId/sessionId、实际结果和截图/文件摘要。任何“不具备环境”均记未验，不勾通过。

### A. 环境准备与完整启停

1. 在隔离环境按 [Windows](INSTALL_WINDOWS.md) 或 [Linux](INSTALL_LINUX.md) 安装四模块独立虚拟环境；Node 使用 `.nvmrc` 的 22.19.0。完成构建及 F4 Alembic 升级。
2. 仅当 `.env` 不存在时从 `.env.example` 复制，填写三模块模型密钥、内部 token、数据库账号及地址。不要覆盖已有配置。本机已准备的项目独立 MySQL 使用 3308，原有 3307 数据库保留；连接地址必须与实际选用实例相符。不要对未备份的业务库试跑迁移。
3. 设置 F3 `F3_MODEL_MODE=REAL`，F4 使用实际 provider；设置实际前端来源（本地 5177），确认 Engine 与 Java 的内部 token 一致。模型密钥不放截图和普通日志。
4. 从包根运行 `scripts/start-all.ps1`（PowerShell 使用 `-ExecutionPolicy Bypass`）或 `bash scripts/start-all.sh`，再运行对应 `health-check`。预期五个后端与前端均就绪；存活但缺配置不得记作 READY。
5. 浏览器打开 `http://127.0.0.1:5177`，注册两个测试账号 A/B。调用一次实际模型任务，确认不是 MOCK，并保存 provider、模型名、耗时及用量，不记录密钥。
6. 空闲时执行 `stop-all`，确认只有记录且身份相符的服务停止；再启动并重新健康检查。端口冲突、陈旧 PID、启动中某服务失败各演练一次，确认不杀无关进程，失败只清理本轮新进程。

通过条件：完整启停可重复、就绪可信、四模块实际模型可连接。当前自动化只覆盖部分脚本行为，不能代替此项。

### B. 样例准备与导入/版本

1. 准备 S1 普通 DOCX：教学目标、6 环节表格（时长 5/12/8/9/4/2，总 40 分钟）、教师/学生/评价列、额外备注列、单元格换行、中文/emoji/竖线、作业。
2. 准备 S2：长单元格与跨页宽表，另包含合并/嵌套表、图片或文本框，保留原稿。准备 S3：空文档、改扩展名的非 DOCX、超过 20 MiB 的输入。
3. A 在“我的教案”导入 S1。预览、确认后记录 V0；核对 6 环节顺序、时长、全部列和课前/课后内容。下载原稿，用 `Get-FileHash -Algorithm SHA256` 与原文件比较，必须完全一致。
4. 修改正文并保存 V1。回到 V0，再前进至 V1；分别下载 DOCX，核对选中的版本与内容、链接目标一致。快速切换版本、浏览器后退/前进、刷新都不得闪回错误正文。
5. 两个标签页同时打开 V1，第一标签页保存 V2，第二页尝试保存旧 V1，预期冲突提示且不覆盖 V2。
6. 导入 S2，核对受支持内容和明确的质量/损失提示；不允许无提示丢内容后仍声称完全保真。导入 S3 应明确拒绝，不产生半个教案和孤立原稿记录。

### C. F1 智能评价、批量和产物

1. 从选定 V1 进入“智能评价”，补齐学科、年级、课题，执行一次真实评价。核对输入 versionId/摘要属于 V1；原稿中已修改的文字不能出现在当前评价输入中。
2. 检查评分、维度理由、批注定位及建议，下载可用产物，用原文逐项核对引用；教师确认评分与建议是否合理。
3. 建立三项批次：两份有效、一份无效输入。确认每项独立显示状态，成功项可查看，失败项原因明确。刷新/重复提交同一已存在任务不能多生成一套收费任务。
4. 在专用环境故意使导出失败（例如测试目录临时无写权限），恢复后只重试产物。原评分与模型调用次数必须不变。不要在业务存储目录上做故障注入。
5. 分别在“排队未开始”和“正在评分”时重启 F1，前者可恢复，后者应明确中断，不自动重复评分收费。整批自动续跑及多进程共享账本尚未交付，不能把手动逐项恢复记成该功能已通过。

### D. F2 设计修改与从零生成

1. 选择 S1 当前版本进入“设计修改”，提出可核对的局部修改要求，例如改变某环节的评价方式，点击“开始设计修改”。核对实际输入仍含目标、作业、额外列及全部课堂环节。
2. 等待真实任务完成，分别检查 best 与 candidate 的实际内容。选择二者之一采用后，对照对应结果逐段核对新版本；不能把别的候选结构/正文当作所选候选保存。
3. 教师复核中自由改写后保存，预期明确标记结构降级或重新解析，不能继续冒用原候选的 VERIFIED 结构。
4. 从零生成一个新教案，完成后进入“查看教案”。记录 lessonId/versionId，再刷新、清除该任务本地缓存、换另一浏览器登录同账号重新打开同任务。预期复用同一服务端采用结果，不重复建教案。
5. 使用 B 打开 A 的任务和采用接口，预期不可访问。任务未完成、失败或取消时不得采用。

### E. F3 真实课堂推演与恢复

1. 选 S1 的明确版本点击“开始课堂推演”，核对实际角色输入/会话材料含 6 环节、时长、教师/学生/评价及额外内容；目标和作业作为上下文保留。仅材料数量为 6 不足以通过，必须查看实际输入及真实课堂事件。
2. 课堂中发送一条人工消息，点击“暂停课堂”，等待一段时间，再“继续课堂”。预期暂停不新增正常教学事件，继续后接续，暂停时间仍计入总预算。
3. 一次让课堂自然结束，另一次用“结束课堂”。分别核对终态/停止原因，不能将提前结束显示为自然完成。确认退出后并发名额释放。
4. 在分析阶段制造一次可恢复失败，使用“重试问题分析”。预期只分析已有事件，事件记录和执行快照不变，可追加分析修订；失败产物可补生成而不重演课堂。
5. 启动后立即取消、网络断开再连接、服务重启、达到输入队列/并发上限各演练一次。预期迟到 Runner 不复活已取消会话；重启中的课堂明确中断，不自动重新收费推演；错误状态可理解并能查看历史。
6. 教师评估角色响应与教学问题是否引用真实事件、行动建议是否可执行，保存质量结论与耗时/调用量。

1. 从选定 S1 版本进入“协同共析”，核对会话来源、分节顺序、原文、结构和绑定一致。

3. 完成每单元取舍后“进入下一单元”，最终“完成本轮”。没有查看/决定完的建议不得被自动视为已完成。
4. 刷新或离开后恢复进度；重复写回同结果必须复用已有平台版本。另一标签页先改变平台 head，再写回旧会话，预期冲突而非覆盖新版本。
5. 测试自由改写不能映射回原单元格的情况，必须明确提示降级，未审阅内容仍保留。
6. 模型慢响应时另一会话应仍可读取；测试同单元双击生成、两标签页生成、会话推进后旧响应返回，预期不重复或覆盖新决定。完成后“结束本次共析”，下载成果并由教师复核。

3. 在看模型结论前，教师独立审阅原稿；将改稿去掉模型/版本标签后做对照评审，比较知识正确、目标—活动—评价一致、学生参与、分层、时间/资源可行性、文字与格式。记录每项“可直接用/修改后可用/不可用”及具体理由。
4. 分别统计 F1 建议误报/漏报及评分分歧，F2 达成修改目标/保持内容的情况，F3 问题引用正确/漏报的情况，F4 建议采纳是否带来实际改进。每个比例写清分子/分母；当前尚未生成任何人工准确率。
5. 由负责人在测试前确定可接受分歧、严重错误和通过比例；建议知识/答案错误、虚构依据、错位写回、静默丢内容先修复，不用平均分掩盖。数字阈值未约定时不得事后挑选“刚好通过”的门槛。
6. 对同一小样本做有限重复试验，核对评分/建议波动和成本；不同教材/学科分开记录，不用总平均掩盖单类失败。规划调用预算后按任务记录实际用量。当前本次文档/格式工作没有执行这组模型实验。
7. 教师签内容意见，工程人员签保存/权限/恢复，负责人签使用范围与限制。要声称真实教学效果提升，还需实际教学验证；模拟角色的表现不能代替学生学习成效。

### 6.7 问题池、账号和浏览器体验（G.1–G.4）

1. 在独立环境让来源同步失败一次，恢复后重试；对比问题 ID/总数、来源任务/版本，预期不重复、不漏失。已有普通重复同步和人工状态保留通过，不需把它们冒充故障重试证据。
2. 将某条问题标为已处理并保存原因；新建一个确实修改对应段落的版本，检查可定位旧问题是否进入待复核而非默认解决。手动复核为仍存在/已解决，核对证据；另一标签使用旧 revision 应冲突。
3. A 发起结果/附件等慢请求后退出，同标签登录 B，再释放旧请求。预期页面、Pinia、缓存不出现 A 的数据。用 B 直接打开 A 的版本下载、F1/F2/F3/F4 地址和修改接口，均拒绝；退出后旧登录态不得继续读写。
4. 桌面 1440px 和窄屏 390px 各走完整导入、预览、版本选择、任务、问题池和共析。重点检查长标题、宽表、长单元格、错误提示、滚动、下载按钮、重试/冲突操作是否可达。已做的五类结果页渲染不能代替此流程。
5. 只用键盘 Tab/Shift+Tab/Enter/Escape 操作主要按钮和对话框，检查焦点可见、进入/关闭后位置合理、没有困住焦点；在计划支持的浏览器分别记录版本和结果，未测的不宣称支持通过。
6. 留证：同步/复核前后 ID 与 revision、慢请求释放时间线、账号切换截图、各视口/浏览器/键盘问题清单。

### 6.8 Word 与 PDF 视觉及可编辑性（H.1、H.2、H.4、H.5）

1. 使用 Microsoft Word 原生打开 S1 原稿、平台 V0/V1 导出、F1 普通/批注稿、F2 BEST_DOCX、F4 最终稿及后续从零生成稿。分别记录 Word 版本、页数及是否有修复警告，不用 Python 能解析代替此项。
2. 另存副本，在每个表格的不同单元格改一个字再保存/重开，确认是真正可编辑单元格；逐段查目标、作业、所有环节/列及备注。F2 六条备注当前缺失，修复前该项不通过。
3. 对 S2 按页检查跨页表头、长单元格分裂、宽表边界、中文字体、图片/文本框位置和页尾内容。列出不支持的样式与页面上已有的提示；不能把“另有原稿可下载”当作生成稿全部保真。
4. 从同一个明确版本下载正式 PDF，逐页与 Word 对照首尾段、总页数、表格和文字；检查没有乱码/缺字/裁切。保留 PDF、对应 DOCX、逐页截图和异常页码；浏览器打印或 F1 批注 PDF 不代替正式版本导出。
5. 工程补验：在独立服务副本中分别制造转换器不可用、超过并发容量、超时；观察错误提示、临时目录及子进程是否清理，再恢复设置成功转换一份文件。不能让失败转换遗留进程占满后续请求。

### 6.9 启停和故障演练（A.6、C.4/C.5、E.5、F.6）

1. 由工程人员在独立验收副本执行，记录该副本数据库、存储根、端口、PID；保存配置与恢复步骤。不要直接修改正在承载已有验收结果的唯一存储。
2. 空闲时停启并记录端口释放/六服务就绪。端口冲突场景：先用自己启动的测试进程占用该副本某服务端口，再启动平台；预期明确失败、测试占用进程不被误杀、只清理此次平台已启动进程，释放占用后可正常启动。
3. 陈旧 PID 场景：在副本 PID 文件写入一个自己启动的测试进程 PID，但故意填入不匹配的创建时间/路径；执行停止应拒绝并保留证据，测试进程仍活着。再用真实匹配身份执行停止，确认只停止相符进程。
4. 启动中故障：把副本其中一个服务的可执行路径/必需配置设为无效，记录失败位置和本轮已启动 PID；确认清理范围及错误原因，恢复原配置后重新启动。不能只看命令退出而不检查子进程/端口。
5. 权限失败及“停止命令退出成功但进程仍在”已有回归；目标部署环境仍需验证日志和操作人员处理方式。失败时 PID 记录应保留，不能手工删除记录假装停止成功。
6. 各模块运行中故障按 6.2、6.4、6.5 分别执行，记录有无额外模型任务。完成后恢复配置、清理自己创建的测试进程、再次健康检查；当前服务持续可用不等于这些故障组合已通过。

### 6.10 历史迁移、修复、备份和恢复（I.1–I.5）

1. 项目负责人提供实际旧版本的脱敏数据和来源版本；工程人员核对需要部署的系统/版本/反向代理配置。没有真实旧数据时，只能保留“合成迁移通过”的范围。
2. 停止副本写入，备份 MySQL、平台 storage、F1 状态/输入/产物、F2 制品、F3 runtime、F4 SQLite，记录一致时间点、行数、文件清单及 SHA256；SQLite 需在停写后复制或用数据库备份机制，不能随意复制活动库后假定一致。
3. 恢复到全新隔离实例，按安装说明运行 Flyway/Alembic。逐一抽查老教案/每个历史版本/归属/原稿、F1 结果、F2 制品、F3/F4 历史；再次迁移应无新增迁移，失败迁移不能留下伪成功记录。
4. 按第 4 节 I.3 链接的修复命令先 dry-run，逐条人工比较正文和候选结构；只对已审核条目准备带双摘要的 manifest。副本 apply 后核对正文/head 不变、结构正确、审计完整；故意使用过期摘要应停止，不强行覆盖。当前无条件式批量回退命令，需按已验证备份恢复。
5. 再恢复到第二个空实例，复核行数/关键文件摘要、登录、历史读取及下载；运行一项新任务验证可继续工作，记录用量及恢复耗时。明确可接受数据损失窗口/恢复时限后再判定是否达标。
6. 在实际目标 Windows/Linux 及 HTTPS/反代环境重做启停、下载、大文件、长任务/流式连接、超时和错误提示。核对部署内容与已验收快照一致；本机启动成功不等于目标部署通过。

### 6.11 容量、费用和最终签收（J.1–J.3、Q5/Q9/Q10）

1. 负责人先写明目标并发用户/任务数、文件大小、最长课堂、响应时间、可接受错误率及预算；工程人员按约定阶梯施压，记录请求/排队/内存/失败与恢复。未约定阈值就不填“容量通过”。
2. 分别验证单实例、实际需要的部署拓扑、任务运行中重启和容量释放。F1/F3 共用持久目录的多进程能力尚未交付；需要该能力时先补实现，不能强行以共享目录压测结果签收。
3. 为 F1/F3 补齐计量后，对有限任务核对请求 ID、成功/失败/重试次数、usage 和供应商账单，验证重试没有意外重跑整项工作。取不到账单/usage 的部分明确列未知。不要把 F2 的 estimatedCost 当实际货币扣费。
4. 汇总 Q1–Q10 与所有未通过/未验项目；每项附修复、复验结果，或经负责人明确签字的限制范围。教师签四模块效果，工程人员签数据/权限/恢复/导出，负责人最后决定能否发布。
5. 对仍需交付的比较页、自动续跑、灰度、回退等功能逐项决定本次发布是否包含；包含则先交付并验收，不包含则在产品及交付范围写清。确认权威提交/标签、构建产物摘要、配置及回退方案后归档。
