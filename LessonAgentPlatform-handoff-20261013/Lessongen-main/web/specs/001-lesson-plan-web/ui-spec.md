# UI/UX 规格

## 1. 设计方向

关键词：安静、可信、专注、具有教学工作台质感。避免常见“AI 产品紫蓝渐变 + 大面积发光卡片”。使用深墨蓝文字、暖白纸张背景、青绿色动作色和少量琥珀色提醒。

设计令牌建议：

```css
--ink-950: #13242f;
--ink-700: #334b59;
--paper-50: #fbfaf6;
--paper-100: #f4f1e8;
--teal-600: #147d78;
--teal-500: #1d948d;
--amber-500: #c88727;
--danger-600: #b84343;
--line: #d9dfdc;
--radius-card: 18px;
--shadow-card: 0 16px 50px rgba(19, 36, 47, .09);
```

中文字体优先：`"Noto Sans SC", "Microsoft YaHei", sans-serif`；教案正文可用 `"Noto Serif SC", "Songti SC", serif`，形成“工具界面/纸面内容”层次。

## 2. 信息架构

```text
/                         工作台/近期任务
/create/generate          生成教案
/create/optimize          优化教案
/jobs/:jobId              任务进度与结果
/jobs/:jobId/research     研究详情（P1，可用抽屉代替）
```

顶部导航只保留 Logo、生成教案、优化教案、历史任务。MVP 不显示虚假头像、积分、会员和通知。

## 3. 工作台

- 首屏一句明确价值：“把课程设想变成可试教、可复盘的教案”；
- 两张主功能卡：从零生成、上传优化；
- 下方近期任务网格，显示课题、科目年级、模式、状态、时间和最终分数；
- 空状态提供两个直接行动按钮；
- 队列繁忙时显示“当前并发 1，前方 N 个任务”。

## 4. 生成页

采用两栏：左侧表单约 7/12，右侧“证据完整度与产出说明”约 5/12。

表单分组：

1. 基本信息：科目、年级、课题、课时；
2. 教学依据：教材版本/摘要、课程标准；
3. 学习设计：预设目标、学情、班级人数、资源；
4. 风格与要求：风格、详细程度、额外约束。

科目、年级、课题始终可见。其余分组可折叠但不得隐藏错误。数组字段使用 chip 编辑器。右栏实时显示证据等级，不把“minimal”渲染为错误，而解释哪些内容需教师复核。

提交按钮文案“开始生成教案”，旁边标注“将调用真实模型并产生费用”。双击由前端锁定 + Idempotency-Key 双保险。

## 5. 优化页

顶部为拖放区：

- 明确只支持 `.docx`、20 MiB；
- 选择后展示文件名、大小、SHA-256 计算状态；
- 显示“不保留原排版，输出使用统一教案模板”；
- 文件错误就地显示，不进入任务队列。

下方表单包含科目、年级、课题、课时、课程标准、学情、优化重点、必须保留内容。提交前摘要同时显示“原文件”和“权威元数据”。

## 6. 任务进度页

页面在 2 秒内出现，不使用全屏永久 spinner。

主要区域：

- 标题与状态徽标；
- 真实阶段时间线：排队、Word 解析（优化）、设计/初评、三类批评、校验、改写、复评、导出；
- 当前轮次、当前 Agent 的公开说明；
- 已用调用次数、Token 和估算费用（默认折叠）；
- “可以离开页面，任务仍会继续”提示。

进度条只在收到事件时前进。等待模型响应时做低频呼吸动画，不能假装百分比增长。

## 7. 结果页

任务进入终态后，同一路由切换为结果视图：

- 顶部：COMPLETED/NEEDS_HUMAN/FAILED、停止原因、最佳版本；
- 主要操作：下载 Word；次要操作：Markdown、JSON；
- 八维评分雷达图 + 数值表；必须显示“内部质量信号”；
- 结构化教案正文采用纸张容器；教学过程用三列“环节/教师与材料/学生与证据”；
- 右侧目录随滚动高亮；移动端变为下拉目录；
- 优化任务增加“本轮主要修改”“未解决问题”和原稿摘要。

FAILED 时不渲染空白结果：展示失败阶段、可执行建议和 recovery 下载；不显示堆栈。

## 8. 动效

动效服务于状态变化：

- 页面进入：180–240 ms，opacity + 8px translate；
- 卡片 hover：150 ms，最多上移 2px；
- 折叠：180 ms；
- 阶段完成：图标描边/填充 220 ms；
- 结果出现：各区块 40 ms stagger，总时长不超过 400 ms；
- 禁止持续粒子、3D 旋转和影响阅读的背景动画。

在 `prefers-reduced-motion: reduce` 下关闭位移、stagger 和呼吸动画，只保留即时状态切换。

## 9. 响应式

- ≥1200：双栏表单、侧边目录；
- 768–1199：双栏比例缩小，目录变抽屉；
- <768：单栏，主按钮固定在安全底部区域，表格转分段卡片；
- 390 宽不横向滚动，长课题允许两行截断。

## 10. 可访问性

- 文字与背景对比度至少 WCAG AA；
- 所有 input 有 label、帮助和错误关联；
- 文件拖放区同时提供按钮；
- 状态使用文字 + 图标 + 颜色；
- SSE 更新通过非打断式 `aria-live=polite`；
- 雷达图旁必须有可读数值表；
- 焦点环不能被主题覆盖。

## 11. 前端状态

Pinia stores：

- `jobDraftStore`：生成/优化草稿，可保存 sessionStorage；
- `jobStore`：近期任务摘要与当前详情；
- `connectionStore`：SSE/轮询状态。

不要把 DOCX File、完整 trace、完整 Prompt 或整份多版本 JSON 长期放入 Pinia/localStorage。
