# 产品规格：教案生成与优化 Web MVP

## 1. 背景与问题

现有 Paper#4 系统已经能通过真实 DeepSeek Agent 与 LangGraph 完成教案生成、批评、校验、改写、复评和 Word 导出，但入口是命令行。用户需要理解参数、等待一个长任务并自行寻找 artifacts，过程不直观，也不适合展示、试用和后续人的实验。

本功能将现有引擎包装为一个面向教师与师范生的网页。第一版只解决两个高频任务：

1. 根据课程信息生成一份新教案；
2. 上传现有 `.docx` 教案并获得优化版本。

## 2. 产品目标

- 用户不编辑 JSON、不接触命令行，即可创建真实 LangGraph 任务。
- 提交后 2 秒内进入任务页，并能看到真实阶段、轮次和状态变化。
- 成功或需人工复核时，可在网页阅读最佳教案并下载 Word、Markdown、JSON。
- 优化任务保留原 Word、规范化中间结果和优化结果的可追溯关系。
- 后端失败必须给出可理解、可重试且不泄露密钥的错误说明。
- Web 层不改变 Paper#4 的 Agent 角色、八维量表、生命周期和最佳版本选择语义。

## 3. 非目标

MVP 不包含：

- 用户注册、组织、角色权限和多人协作；
- 浏览器内完整 Word 排版编辑器；
- 对原 Word 样式逐像素保真；优化输出使用系统标准 Word 模板；
- 课程标准知识库管理、向量数据库和完整 RAG；
- Paper#1 标注、Paper#2 人机导航、Paper#3 课堂模拟；
- 手机原生应用、微信小程序；
- 多机集群、Celery/Redis、Kubernetes；
- 用内部 Judge 分数宣称真实教学成效。

## 4. 用户与场景

### 4.1 主要用户

- 新教师：输入基本课程信息，得到结构完整且可继续编辑的教案；
- 师范生：通过过程页理解教案如何被多角色检查和迭代；
- 项目演示者：稳定展示两个功能、评分变化、意见与产物。

### 4.2 用户故事

#### US-01 生成教案（P0）

作为教师，我填写科目、年级、课题等信息并提交，希望网页持续显示生成阶段，最终可预览和下载教案。

验收：

- 科目、年级、课题必填；课时默认 45 分钟；
- 课程标准、教材摘要、学习目标、学情等为可选，但界面解释缺失会带来的核验边界；
- 提交创建唯一任务，重复点击不创建多个任务；
- 最终展示最佳版本而非机械展示最后版本；
- `completed` 与 `needs_human` 均可下载已有最佳产物；`failed` 显示诊断和可用 recovery 文件。

#### US-02 上传 Word 优化（P0）

作为教师，我上传已有 `.docx` 教案并补充必要的课程信息，希望系统理解原稿、保留其有价值内容，再运行三类 Critic 和 Rewriter 输出优化稿。

验收：

- 只接收真正的 OOXML `.docx`，默认最大 20 MiB；拒绝 `.doc`、`.docm`、加密包、损坏包和伪装扩展名；
- 必须保存原文件哈希；文件名不能决定服务端路径；
- 提取正文和表格，并规范化为 `LessonPlanDocument`；
- 页面明确告诉用户“输出为系统标准模板，不保证保留原排版”；
- 元数据不确定时使用用户填写值作为权威值，禁止模型擅自改变科目、年级、课题和课时；
- 优化结果至少可查看原稿摘要、最佳版本、关键修改和未解决意见。

#### US-03 查看进度（P0）

作为用户，我希望提交后不用一直盯着加载动画，而能知道系统正在设计、写作、评审、批评、校验、改写还是导出。

验收：

- 状态来自后端事件，不使用按时间伪造的百分比；
- 断网重连或刷新页面后可由任务详情恢复；
- SSE 不可用时退化为 2 秒轮询；
- 不向前端暴露隐藏思维链、完整 Prompt、API Key 或内部磁盘路径。

#### US-04 查看结果（P0）

作为用户，我希望阅读结构化教案、评分和关键修改，并下载文件。

验收：

- 教案按基本信息、设计主线、目标、重难点、过程、评价、差异化、作业、板书等分区；
- 显示八维评分与“内部评价，非正式效果结论”提示；
- 显示最终状态、停止原因、最佳版本和最后版本；
- 产物下载必须通过 artifact ID，不允许前端提交任意文件路径；
- 优化任务显示原稿与优化稿的摘要级差异，完整字段级 diff 可后续增强。

#### US-05 查看近期任务（P1）

作为用户，我希望看到最近生成和优化的任务，能按类型与状态筛选并继续查看结果。

验收：

- 默认按创建时间倒序；
- 分页，每页默认 12 条；
- 支持 `mode`、`status` 筛选；
- 卡片只显示摘要，不加载大型结果 JSON。

## 5. 功能需求

### FR-01 生成表单

必填：`subject`、`grade`、`topic`。
默认：`durationMinutes=45`、`detailLevel=showcase`、`lessonStyle=choose_the_best_fit_for_this_topic`。
可选：课程说明、教材版本、教材摘要、课程标准、目标、学情、班级人数、资源、其他要求。

数组输入采用可增删标签项，不让用户手写分号或 JSON。

### FR-02 优化表单

必填：Word 文件、科目、年级、课题。
可选：课时、教材版本、课程标准、学情、优化重点和必须保留内容。

“优化重点”进入任务约束；“必须保留内容”必须进入结构化预处理与 Rewriter 约束，不能只是界面备注。

### FR-03 异步任务

- 创建任务返回 HTTP 202 与 `jobId`；
- 状态机：`QUEUED → PREPROCESSING? → RUNNING → EXPORTING → COMPLETED | NEEDS_HUMAN | FAILED`；
- 状态只允许向前迁移，终态不可被后台轮询覆盖；
- Java 与 Python 都使用同一个 `correlationId/jobId` 记录日志；
- 同一 `Idempotency-Key` 和相同请求摘要在 24 小时内返回原任务。

### FR-04 任务进度

对外事件只包含：序号、公开阶段、轮次、当前版本、公开说明、发生时间。内部 trace 可保存更多内容，但不可原样发送浏览器。

### FR-05 结果与产物

- Spring Boot 从 Python 结果映射状态并登记产物；
- 结构化最佳教案供网页展示；
- DOCX/Markdown/JSON/trace/process-report 作为产物元数据记录；
- 浏览器默认只显示 DOCX/Markdown/JSON，trace 和过程报告放在“研究/调试”折叠区；
- 下载响应设置安全文件名、准确 MIME、`Content-Disposition: attachment`。

### FR-06 错误与重试

- 余额不足、鉴权错误、网络失败、Word 解析失败、结构规范化失败、生成失败必须使用稳定错误码；
- 前端显示可执行建议，不显示 Java/Python 堆栈；
- 重新运行必须创建新任务并通过 `retryOfJobId` 关联旧任务，不能覆盖旧 artifacts；
- MVP 不承诺运行中取消；页面应明确“任务提交后暂不支持取消”。

## 6. 状态映射

| Python `PipelineResult` | Web 任务状态 | 用户含义 |
| --- | --- | --- |
| `completed` | `COMPLETED` | 闭环正常结束，有最佳版本 |
| `needs_human` | `NEEDS_HUMAN` | 有可用最佳版本，但需教师检查 |
| `failed` 且有 recovery | `FAILED` | 闭环失败，可下载恢复稿 |
| `failed` 且无版本 | `FAILED` | 未形成可用教案 |

`stop_reason` 必须原样保存为独立字段；不能只保留模糊中文消息。

## 7. 业务规则

- BR-01：任何 API Key 只存在 Python 服务端环境变量中。
- BR-02：公开 API 不接受客户端指定 `runId`、存储路径、Prompt 路径或模型名。
- BR-03：同一任务只有一个 active engine run。
- BR-04：最佳版本与最后版本可能不同，必须分别展示。
- BR-05：优化上传的原 Word 永远不被覆盖。
- BR-06：Word 规范化失败时不得退化为“把整段文本塞进一个字段并假装成功”。
- BR-07：文件和 JSON 的 SHA-256 用于完整性，不用作访问授权。
- BR-08：对外进度只依据真实事件；长时间无新事件显示“仍在等待模型响应”，不虚增百分比。
- BR-09：内部 Judge 评分必须标注“内部质量信号”。
- BR-10：MVP 最大并发真实生成数默认为 1，其余任务排队，以控制费用与 402 风险。

## 8. 非功能需求

### 性能

- 创建任务 P95 < 2 秒（不等待模型）；
- 查询任务 P95 < 300 ms（不读取完整 trace）；
- SSE 事件延迟目标 < 3 秒；
- 20 MiB DOCX 上传在本机网络下有明确进度。

### 可靠性

- Java 重启后从 MySQL 恢复非终态任务，并向 Python 查询真实状态；
- Python 重启后从 run 目录的 trace/result 恢复可判断状态，不能把未知任务标成成功；
- 文件写入使用临时文件后原子替换；
- 数据库状态更新使用乐观锁版本号。

### 安全与隐私

- 限制 MIME、扩展名、OOXML magic、解压文件数、单项大小和总解压大小；
- 解压必须阻止 Zip Slip；拒绝宏、外链模板和加密文档；
- 日志、错误和 SSE 均去除密钥、Prompt 全文、原文全文和本地绝对路径；
- 文件下载必须由数据库中的 artifact 归属校验生成；
- 默认保留 30 天，可配置并提供后续清理任务。

### 可访问性与兼容性

- 桌面 1440/1280、平板 768、移动端 390 宽度可用；
- 键盘可完成表单、提交、切换和下载；
- 尊重 `prefers-reduced-motion`；
- 状态不只依赖颜色表达。

## 9. 成功指标

MVP 工程验收：

- 10 次生成任务中至少 9 次能进入明确终态；
- 5 种结构不同的真实 DOCX 中至少 4 种能正确提取正文和表格并进入优化；
- 所有非失败终态均能下载存在且哈希匹配的 Word；
- 刷新页面后任务状态和结果不丢失；
- 自动化测试不调用真实 DeepSeek；真实验收另使用受控预算运行。

研究指标不在 MVP 自动判定：教师满意度、教案质量提升和真实课堂效果必须另行设计人的实验。

## 10. 开放问题

- OQ-01：最终产品中文名与 Logo；暂用“灵犀教案”。
- OQ-02：首个演示是否需要账号登录；暂按本地单用户实现，但表保留 nullable `owner_id`。
- OQ-03：优化是否必须逐字保留用户指定段落；MVP 支持“必须保留内容”语义约束，不保证 Word 样式不变。
- OQ-04：是否允许上传课程标准附件；列为下一规格，不阻塞当前 MVP。
