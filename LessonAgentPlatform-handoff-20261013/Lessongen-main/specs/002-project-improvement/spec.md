# 改进需求规格

## 1. 问题与目标

Lessongen 已具备真实模型生成/优化、结构化教案、审查裁决、Word 导出及 Web 入口，但“能够生成一次”尚不等于可重复开发、可解释审查或可研究比较。当前最直接的问题是多份代码和配置混用、运行来源不透明，以及生成 v0 可被内部 Judge 单独判为 `quality_passed`，绕过三 Critic。随后才是可维护性、资料依据、多智能体并发和教学成效证据。

目标是建立一条可审计链：**确定的源代码/配置 → 真实模型调用 → 可追踪审查与修改 → 稳定产物 → 独立质量与人的评价**。其中“内部质量”与“实际教学效果”必须分开。

## 2. 用户与典型场景

- 开发者：只启动 F 仓库，能从健康页或启动输出确认代码、配置和模型来源，不再在 C/F 之间猜测。
- 教师/师范生：生成的教案至少经过一次独立审查；没有值得修改的意见可以保持原稿，但页面必须如实写“已审查、未改写”。
- 研究者：能够固定任务集、模型/Prompt/知识配置，比较不同线路的版本、成本、用时、意见质量与人工评价。
- 维护者：一次改动在 CI 中触发 Python、Java、Vue 的离线回归；失败可定位到明确阶段，且不泄露密钥。

## 3. 非目标与边界

- 本规格不是重写整个产品，也不把 LangGraph 流程迁移到 Java。
- P0/P1 不引入 Redis、向量数据库、多机调度、知识库管理后台或强制更换模型供应商。
- “Critic 并发”只讨论同轮独立审查；Validator、Rewriter、Judge 的依赖仍按序执行。未证实收益前，不以并发替换基线。
- RAG 不等于“上传任意 PDF 就视为权威课程标准”；版权、版本、适用学段和准确引用必须先成立。
- Paper#3 adapter 不等于课堂模拟已接入主图。没有经双方确认的报告契约及后验证协议，不开启主图开关。
- 不用内部八维分数或模型自评宣称学生学习效果；人的实验需获得导师、学校与参与者相应批准。
- P3 的“发布”不默认公开互联网部署。当前 MVP 无登录/权限，未满足公开服务的数据保护条件。

## 4. 需求与验收标准

### P0 · 工程基础

**P0-01 唯一代码来源。** 正式开发、CI、IDEA 和启动脚本只认 `F:\comalesson\Lessongen`。启动必须输出或可查询非敏感构建指纹：仓库根、Git commit/dirty 标志、Python 包实际路径、配置文件路径与哈希、Writer 最大输出、状态/产物根目录；Java 也应能识别自身构建来源。不能将 API Key、Token 或完整 Prompt 放进健康响应。

验收：故意让环境中的旧 editable 包指向 C 盘，F 启动器仍加载 F；若服务进程占用目标端口或源码与配置指纹不一致，明确提示并拒绝“看似成功”的启动。旧数据保持可读。

**P0-02 可复现环境。** 提供一个从空环境安装的受支持流程，锁定 Python、Java、Node 及关键依赖；不把 C 盘绝对路径、真实密钥和本机 `pip freeze` 原样当锁文件。完整产品只保留一套主推数据库路径：根 Compose 的 MySQL 3307；本机 MySQL 3306 仅作为旧实例保留，不再进入一键启动或验收路径，二者不可混写。

验收：新环境中 `import paper4_pipeline` 指向 F；Python/Java/Vue 离线测试与构建通过；`--check` 不付费且对缺失变量、错误端口和目录给出可操作提示。

**P0-03 自动 CI 与提交卫生。** GitHub PR 自动跑三端离线测试、类型/格式/契约检查和密钥扫描；不在 CI 调用真实 DeepSeek。CI 要保存失败测试报告，明确 Docker/MySQL 集成测试是必跑、条件跑还是专门工作流，不能静默跳过后显示“全绿”。

验收：新 PR 中蓄意破坏一个 Python、Java 或 Vue 测试均能使检查失败；`.env`、教案原文、运行 artifacts 不进入提交；现有未提交改动按模块审查与小批提交，不强推、不清空工作树。

### P1 · 行为、代码与契约

**P1-01 生成初稿的审查语义。** 默认生成模式在 `v0` 通过内部 Judge 时，仍至少完成一次 Subject、Pedagogy、Alignment 独立审查与 Validator 裁决；随后才能宣称“完成独立审查”。内部高分不能单独作为跳过 Critic 的理由。无可执行意见不强制改写；有有效意见则按现有 Rewrite/Verifier/复评处理。优化模式保持其既有初审要求。

P1 已冻结的工程语义：默认策略 ID 为 `at_least_one_independent_review`，仅显式设置 `judge_first_fast_path` 才允许旧路线；“已完成独立审查”要求同一轮三位配置的 Critic 都有完成事件，且该轮存在 Validator 裁决。无可执行意见沿用 `no_actionable_feedback`，保留 v0、不虚构 v1；初审预算不足为 `needs_human` + `budget_exceeded`；已审查但无改写轮次且有接受意见为 `needs_human` + `max_rounds`。Critic 失败不得宣称审查完成。该默认值的研究成本取舍仍需导师确认，见 D04–D06。

验收：回放“v0=8.275、门槛=8.0”的固定状态，能看到三 Critic 与 Validator；可由配置显式选择旧的 `judge_first_fast_path` 作为实验对照，但产物与 UI 必须准确区分“仅内部评分”和“完成独立审查”。预算不足、Critic 失败和无可执行意见各有明确状态/停止原因，不伪造修改。

**P1-02 图模块化且行为兼容。** 将 `orchestration/graph.py` 的节点逻辑、路由/状态转换、trace/用量记录分开，但保留 `Paper4Workflow` 公共入口、现有 `LessonTask`/`PipelineResult` 与导出语义。先写 characterization tests，再按节点小步移动，避免“大重构 + 算法改动”同时发生。

验收：固定输入和假 Agent 的节点顺序、状态迁移、失败降级、最佳版本选择及关键 trace 字段不变；格式调整须显式升版本并提供兼容读取。真实模型措辞不作为逐字比较基准。

**P1-03 统一模型调用账本。** 设计师、Writer、Critic、Validator、Rewriter、Judge 与 DOCX Normalizer 共用调用记录规范，覆盖成功、重试、截断、网络失败、取消和部分完成。每次真实尝试只计一次；成本是按冻结费率估算，不伪称账单金额。

本轮实现以每次 Provider 尝试为一条追加记录；上游未返回 usage 时 Token 和费用为 `null`（已知金额只是部分和），截断可从异常携带的 usage 恢复。账本写入失败立即终止，不因本地磁盘错误再次调用付费模型。进程被操作系统强制杀死时无法保证最后一条记录落盘，不能把它解释为零费用；恢复与账单核对应在后续运维设计中处理。

验收：trace、`run_result`、Web 快照的总调用/Token/估算费用可对账；异常路径不归零、不重复计数；记录模型 ID、角色、阶段、Prompt/config 指纹和完成原因，但不记录密钥或未授权的教案全文。

**P1-04 内部契约与前端关键路径。** 以 Python API 的受控 OpenAPI/JSON Schema 输出作为内部契约基线，Java Engine DTO 通过生成或 CI 差异检查保持一致；生成代码只负责协议模型，业务映射仍在显式 Adapter。前端补 Store 与关键 E2E：任务创建、轮询/SSE 恢复、401/402/超时、失败/recovery、优化有改动与无改动。

验收：任意一端改变必需字段或枚举后，契约测试失败而非上线后 422；UI 不把上传原件或候选稿展示成已交付优化稿，刷新后状态正确。

### P2 · 受控能力演进

**P2-01 Critic 并发试验。** 以现有顺序三 Critic 为基线，仅当 P1 用量/trace 账本稳定后，为同轮三 Critic 引入有界并发与开关。每个 Critic 读取同一版本快照，不读取本轮同行输出；聚合顺序、ID 去重、预算、超时与部分失败策略保持确定性。

验收：同任务重复运行时结构和事件顺序可审计；并发不突破模型请求并发限制和任务预算。与顺序基线比较端到端耗时、费用、失败率、意见差异；只有明确收益才设为默认。

**P2-02 权威资料检索试验。** 建立课标/教材授权状态、版本、适用范围和片段出处登记；按学段、学科、课题检索相关片段供角色使用。没有匹配权威来源时保留“待核验”，不得凭检索得分补造条款。先从小规模人工核验语料和确定性检索开始，是否使用向量索引由质量对照决定。

验收：每条引用可回到原文/版本；错误学段、过期资料和无授权内容被排除；在冻结任务集上比较无检索/检索的准确性、幻觉、成本与用时。

**P2-03 Paper#3 后验证试验。** 与 Paper#3 负责人确认 `SimulationReport` 的语义、角色配置、时间估计、证据可信度和缺失字段；先用保存的报告测试现有 adapter，再以独立后验证节点处理实际模拟证据。模拟建议只能成为待 Validator 裁决的意见，不得取代真实课堂或人的评价。

验收：Paper#3 不可用时 Paper#4 正常完成并标注“未模拟”；报告与教案版本一一对应；开启/关闭时差异、成本与误报可复核。

**P2-04 模型/Thinking 对照。** 固定任务集、Prompt、角色知识、路由与预算，单独改变模型或 Thinking 参数；记录供应商可用性、输出限制、JSON 合规率、时延与成本。不同实验配置有唯一 ID，不在同一运行中暗换模型。

验收：预注册对照变量与判定指标；任何新模型适配通过结构输出、失败会计、预算和脱敏测试后才进入候选。

### P3 · 研究与发布

**P3-01 人工评价。** 与导师确定教案类型、学科、固定任务集、盲评量表和评分者；至少比较原稿、单轮/多轮、不同 Critic/知识配置，并报告评分者一致性、差异区间、修改是否真实、用时和成本。实际试教或学校使用需要单独方案与批准。

**P3-02 数据与伦理。** 教师/师范生参与需知情同意；学生、学校和教案材料脱敏与授权；建立留存期限、访问控制、删除机制和外部模型数据传输告知。未取得批准时只做合成或授权样例离线评价。

**P3-03 开源/发布门槛。** 明确代码、样例教案、课标素材和图片的权利归属，选择许可证；文档说明本地原型限制、费用、隐私和已知边界。公开部署前另行规格化身份认证、配额、隔离、滥用防护和数据删除；CI 通过不等于可公开上线。

## 5. 总体验收规则

每项需求必须有：测试/测量方法、失败示例、产物路径、负责人或待确认责任、成本与回滚路径。没有独立证据时状态只能是 `planned` 或 `experiment`，不能标为完成。P2/P3 进入实施前必须重新评审 P0/P1 的数据质量和导师的研究方向。
