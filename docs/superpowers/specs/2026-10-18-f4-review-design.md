用户已在聊天中确认五项修改并授权完成测试、提交、推送及可行时合入 main。本次不实现撤销决定。

## 用户可见行为

1. 删除章节导航底部的实现规则备注。
2. 表格修订保留格内真实换行，整行内容不得塞入一个格子。
3. 修改已有表格必须定位原格；仅独立新增内容可以作为章节补充。定位失败保持正文不变，明确说明原因，不默认追加替换稿。
4. 增加“回看上一单元”和已完成章节导航，显示“已完成 · 回看中”、原建议、选择结果及当前修订稿；提供“返回当前单元”。回看不生成建议、不修改选择、不改变服务器进度。刷新恢复实际待处理单元。
5. 一条建议可以原子地修改多个段落/列表项/单元格，及在明确段落之后插入补充段落。任何目标失效则整条建议不应用。

## 修订协议

新增可选 edits 数组，每项含 operation（replace 或 insert_after）、block_id、可选 row_id/column_index 或 item_index、expected_text（完整原节点文本）、text（完整新节点文本，使用真实换行）。字段不能指向本章以外的内容。结构化上下文包含可编辑节点和原文；仍以章节为教师决策单元。

旧建议保留兼容路径：单节点精确替换继续支持；schema 1.1 中能够严格识别的完整表格行投影按相同列数及行标识解码后分格应用；schema 1.0 没有明确转义约定，拒绝整行重建，仍支持原始单格文本修改；整段连续段落的精确目标可改为新的段落序列。无法明确对应的跨格、重复目标或过期内容保持不变。不得全局替换字面量反斜杠或按任意竖线拆格。

持久化 edits 使用可空 JSON 列，旧记录解释为空数组，不改写已保存决定与历史版本。生成审计与结构化校验在写入前拦截不一致建议。替换失败候选支持 can_append=false；此时仅展示无法应用说明与保留原稿操作，不提供把替换稿追加的按钮。独立 append 建议沿用已有采纳路径。

节点修订仅由声明支持该能力的 replace_or_append_v2 策略执行；保留旧策略快照的会话不得越过其策略执行替换。共析结束后仍可从最终结果进入只读回看，再返回最终结果。
